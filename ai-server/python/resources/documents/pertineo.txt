0. Pertineo 시스템
Pertineo 역량 평가 시스템은 지원자의 역량을 세 가지 관점으로 점수화해서, 숫자로 비교할 수 있게 만든 평가 도구이다.

아래 3가지 측면에서 지원자의 역량을 평가한다.
X축 = '얼마나 깊이 공부했는가?'  (학습수준)
Y축 = '이 직무에 얼마나 잘 맞는가?'  (직무 적합도)
Z축 = '실제로 성과를 낼 수 있는가?'  (수행역량)

점수 범위 : 1.0점 ~ 5.0점, 1.0이 최하, 5.0이 최고
점수 단위 : 0.1점 단위로 세분화 가능(ex 4.3, 4.4)
평가 축 : X, Y, Z 세 가지 각각 독립적으로 평가

점수 산정 전에 적용될 규칙들이 있다.

1. Gate 규칙
특정 조건이 없으면 일정 점수 이상으로 올라가는 문이 아예 닫혀 있는 규칙이다.
조건들은 아래와 같다.

- 정량 KPI(수치 성과)가 없음 : 4.4점 이상 불가, 성과를 숫자로 증명 못 하면 최고 수준이라 볼 수 없음
- 실행 반복 구조(Loop)가 없음 : 4.2점 이상 불가, 한 번만 해본 것은 진짜 역량이라 보기 어려움
- 직무/산업 경험이 부족함 : 4.3점 이상 불가, 직무에 맞지 않으면 아무리 잘해도 한계가 있음
 - 결과를 재현할 수 없음 : 4.5점 이상 불가, 우연한 성과는 최고 수준의 역량으로 인정할 수 없음

2. Cap 규칙
점수의 천장(상한선)을 강제로 제한하는 규칙이다.
조건들은 아래와 같다.

- 업종별 KPI 연결 없음 : 최대 4.0점, 실적은 있지만 업종 맥락의 수치 지표가 없음
- OKR 구조 없음 : 최대 4.2점, 목표 설정과 결과 연결 구조가 없음
- 재현성 설명 불가 : 최대 4.3점, "어떻게 다시 할 수 있는가"를 설명 못 함
- 확장성 설명 불가 : 최대 4.4점, "다른 상황에도 쓸 수 있는가"를 설명 못 함

3. Gate와 Cap의 적용
Gate = 입장 자체를 막는 것  →  '4.4점 이상 구간에는 들어올 수 없음'
Cap  = 점수 상한을 막는 것  →  '어떤 점수가 나와도 4.2점까지만 인정'
Cap이 Gate보다 항상 먼저 적용된다. (Cap 우선 원칙)
즉, Cap으로 4.2점 상한이 걸리면 Gate 조건과 상관없이 4.2점 이상은 불가하다.

4. Pertineo 평가 순서
Step 1) Domain 확인 : 지원자가 어느 분야(계열)에 해당하는지 분류, "이 사람은 공학계열인가, 경영계열인가?"
Step 2) KPI 확인 : 정량적인 성과 지표가 있는지 확인, "숫자로 증명한 성과가 있는가?"
Step 3) Role 확인 : 직무에 맞는 역할을 실제로 해봤는지 확인, "이 직무의 역할을 직접 수행해봤는가?"
Step 4) Loop 확인 : 실행-측정-개선 구조가 있는지 확인, "한 번만 한 건지, 반복한 건지?"
Step 5) 재현성 확인 : 같은 성과를 다시 낼 수 있는지 확인, "어떻게 했는지 다시 설명할 수 있는가?"
Step 6) 기본 점수 계산 : X, Y, Z 각각의 기본 점수를 산출(X, Y, Z 점수 초안 계산)
Step 7) Gate 적용 : 점수 구간 진입 자격을 확인하여 차단, "이 점수 구간에 들어올 자격이 있는가?"
Step 8) Cap 적용 : 상한선을 초과하지 않도록 최종 조정, "점수 상한을 넘지 않는가?"

이 순서를 건너뛰고 점수를 주면 안 된다. 예를 들어 KPI 확인도 하지 않고 바로 4.5점을 주는 것은 잘못된 평가이다.
순서대로 확인하고, 조건이 충족될 때만 해당 점수 구간에 접근하도록 한다.
