0. Pertineo 시스템
Pertineo 역량 평가 시스템은 지원자의 역량을 세 가지 관점으로 점수화해서, 숫자로 비교할 수 있게 만든 평가 도구이다.

아래 3가지 측면에서 지원자의 역량을 평가한다.
X축 = '얼마나 깊이 공부했는가?'  (학습수준)
Y축 = '이 직무에 얼마나 잘 맞는가?'  (직무 적합도)
Z축 = '실제로 성과를 낼 수 있는가?'  (수행역량)

점수 범위 : 1.0점 ~ 5.0점, 1.0이 최하, 5.0이 최고
점수 단위 : 0.1점 단위로 세분화 가능(ex 4.3, 4.4)
평가 축 : X, Y, Z 세 가지 각각 독립적으로 평가

점수 산정 전에 적용될 규칙들이 있다.

1. Gate 규칙
특정 조건이 없으면 일정 점수 이상으로 올라가는 문이 아예 닫혀 있는 규칙이다.
조건들은 아래와 같다.

- 정량 KPI(수치 성과)가 없음 : 4.4점 이상 불가, 성과를 숫자로 증명 못 하면 최고 수준이라 볼 수 없음
- 실행 반복 구조(Loop)가 없음 : 4.2점 이상 불가, 한 번만 해본 것은 진짜 역량이라 보기 어려움
- 직무/산업 경험이 부족함 : 4.3점 이상 불가, 직무에 맞지 않으면 아무리 잘해도 한계가 있음
 - 결과를 재현할 수 없음 : 4.5점 이상 불가, 우연한 성과는 최고 수준의 역량으로 인정할 수 없음

2. Cap 규칙
점수의 천장(상한선)을 강제로 제한하는 규칙이다.
조건들은 아래와 같다.

- 업종별 KPI 연결 없음 : 최대 4.0점, 실적은 있지만 업종 맥락의 수치 지표가 없음
- OKR 구조 없음 : 최대 4.2점, 목표 설정과 결과 연결 구조가 없음
- 재현성 설명 불가 : 최대 4.3점, "어떻게 다시 할 수 있는가"를 설명 못 함
- 확장성 설명 불가 : 최대 4.4점, "다른 상황에도 쓸 수 있는가"를 설명 못 함

3. Gate와 Cap의 적용
Gate = 입장 자체를 막는 것  →  '4.4점 이상 구간에는 들어올 수 없음'
Cap  = 점수 상한을 막는 것  →  '어떤 점수가 나와도 4.2점까지만 인정'
Cap이 Gate보다 항상 먼저 적용된다. (Cap 우선 원칙)
즉, Cap으로 4.2점 상한이 걸리면 Gate 조건과 상관없이 4.2점 이상은 불가하다.

4. Pertineo 평가 순서
Step 1) Domain 확인 : 지원자가 어느 분야(계열)에 해당하는지 분류, "이 사람은 공학계열인가, 경영계열인가?"
Step 2) KPI 확인 : 정량적인 성과 지표가 있는지 확인, "숫자로 증명한 성과가 있는가?"
Step 3) Role 확인 : 직무에 맞는 역할을 실제로 해봤는지 확인, "이 직무의 역할을 직접 수행해봤는가?"
Step 4) Loop 확인 : 실행-측정-개선 구조가 있는지 확인, "한 번만 한 건지, 반복한 건지?"
Step 5) 재현성 확인 : 같은 성과를 다시 낼 수 있는지 확인, "어떻게 했는지 다시 설명할 수 있는가?"
Step 6) 기본 점수 계산 : X, Y, Z 각각의 기본 점수를 산출(X, Y, Z 점수 초안 계산)
Step 7) Gate 적용 : 점수 구간 진입 자격을 확인하여 차단, "이 점수 구간에 들어올 자격이 있는가?"
Step 8) Cap 적용 : 상한선을 초과하지 않도록 최종 조정, "점수 상한을 넘지 않는가?"

이 순서를 건너뛰고 점수를 주면 안 된다. 예를 들어 KPI 확인도 하지 않고 바로 4.5점을 주는 것은 잘못된 평가이다.
순서대로 확인하고, 조건이 충족될 때만 해당 점수 구간에 접근하도록 한다.

X축(학습 수준)에 대한 설명이다.

X축은 단순히 '많이 공부했는가'를 보는 게 아니다. 배운 것을 실제로 써먹을 수 있는 구조로 만들 수 있는지를 본다.

X축에서 확인하는 역량은 아래와 같다.
- 이론을 실제 문제에 적용할 수 있는가?
- 변수(원인)와 결과를 연결해서 설명할 수 있는가?
- 왜 이 방법을 선택했는지 근거를 댈 수 있는가?
- 데이터와 성과 지표(KPI)를 연결할 수 있는가?

X 축에 대한 점수 산정 기준은 아래와 같다.
- 5.0(이론을 직접 실행 모델로 설계한 최고 수준) : 세계적 학술지 논문 발표, 특허 등록, 전략 전체를 직접 설계하고 KPI까지 설정, 변수 정의 가능, 인과관계 설명 가능, KPI를 설계에 반영했음. 하나라도 없으면 4.9 이하
- 4.7~4.9(핵심 분석·설계를 수행할 수 있는 고급 수준) : 주요 논문 발표 경험, 핵심 기술/시스템 설계 참여, 데이터 기반 성능 개선 경험, 구조 기반 해석 가능, 설계 또는 분석 경험 있음, 성능 개선 경험 있음
- 4.4~4.6(실무에 바로 적용 가능한 수준) : 프로젝트에서 직접 분석 수행, 관련 툴 활용 경험, 데이터 분석 후 실행 연결 경험, 분석 또는 구현 경험 있음, 구조 이해 있음, 단순 구현이면 4.3 이하
- 4.1~4.3(기본은 알지만 독립 설계는 아직 어려운 수준) : 실험 또는 개발 프로젝트 참여, 이론을 일부 적용한 경험, 실험/개발 경험 있음, 구조 설명이 약하면 이 구간
- 3.7~4.0(기초 실무는 가능한 수준) : 팀 프로젝트 참여, 기본 개발 또는 실습 경험, 팀 프로젝트/실습 경험 있음, 단순 수행 중심
- 1.0~3.6(이론 중심이거나 경험이 거의 없는 수준) : 수업 이수, 교재 학습, 관련 경험 없음, 실무 연결 부족, 설계 불가

Y축(직무적합 수준)에 대한 설명이다.

Y축은 '이 지원자가 이 직무에 딱 맞는 사람인가?'를 4가지 요소로 평가합니다.
점수는 Role + Skill + Domain + Behavior를 평균한 점수이다.
다시 말하면 (역할 적합성 + 기술 적합성 + 도메인 이해 + 행동 적합성) / 4 로 점수를 산정한다.

Role : 역할 적합성, 이 직무의 역할을 직접 해봤나요?, "이 사람이 그 역할을 실제로 수행한 적 있는가?"
5.0점 → 그 직무를 이끄는 리더 역할을 해봤다
4.5점 → 핵심 역할을 혼자 수행해봤다
4.0점 → 부분적인 역할을 수행해봤다
3.0점 → 보조 역할만 했다
2.0점 → 관련 경험이 없다
주의:  '관심 있다', '배우고 싶다' → 경험으로 인정 안 됨

Skill : 기술 적합성, 필요한 기술을 실제로 쓸 수 있나요?, "배웠다가 아니라, 실제 업무에 쓸 수 있는가?"
5.0점 → 핵심 기술을 완전히 숙련해서 쓸 수 있다
4.5점 → 실무에 바로 투입 가능한 수준
4.0점 → 프로젝트에서 써본 경험이 있다
3.0점 → 기초 수준 (교육에서만 배움)
2.0점 → 없음
주의:  '배웠다', '알고 있다' → Skill 높게 주면 안 됨

Domain : 도메인 이해, 이 산업/분야를 구조적으로 이해하나요?, "이 분야가 어떻게 돌아가는지 설명할 수 있는가?"
5.0점 → 산업 구조 + 핵심 변수 + 전체 흐름을 설명 가능
4.5점 → 주요 프로세스를 이해함
4.0점 → 개념은 알지만 구조 설명이 약함
3.0점 → 용어는 알지만 단편적 지식
2.0점 → 없음
주의:  '이 분야 관심 있음' → Domain 점수 주면 안 됨

Behavior : 행동 적합성, 일하는 방식이 이 직무에 맞나요?, "이 조직의 방식으로 일할 수 있는가?"
5.0점 → 팀을 이끌며 데이터 기반으로 의사결정함
4.5점 → 협업 및 실행 능력이 뛰어남
4.0점 → 기본적인 협업은 가능함
3.0점 → 지시받아서 수행하는 수동적 스타일
2.0점 → 조직 방식에 적합하지 않음
주의:  '성격 좋음', '친화력 있음' → Behavior 점수 아님

Y 축에 대한 점수 산정 기준은 아래와 같다.
- 5.0(이 직무의 실행 구조 전체를 재현 가능한 수준) : 핵심 프로젝트 리더 경험, KPI 기반 의사결정 수행, Role/Skill/Domain/Behavior 모두 높음, 4가지 요소 모두 충족, KPI 기반 의사결정 경험. 하나라도 약하면 4.9 이하
- 4.7~4.9(프로젝트 리더로 활약 가능한 고급 수준) : 대기업/주요 프로젝트 리더 경험, 데이터 기반 실행 경험, Role과 Skill 일치도 높음, 데이터 기반 실행 경험 있음
- 4.4~4.6(실질적으로 기여할 수 있는 고급 실무 수준) : 주요 프로젝트에서 실질 기여, 직무 관련 데이터 분석 경험, 핵심 기여 경험 있음, KPI 일부 기여 있음, KPI 없으면 4.3 이하
- 4.1~4.3(실무에서 일부 기여할 수 있는 기초 실무 수준) : 직무 관련 프로젝트 수행, 관련 학술대회 발표 경험, 직무 관련 경험 있음, 역할/기술/산업 일부만 일치
- 3.7~4.0(기본 직무 수행은 가능한 수준) : 보조 역할 참여, 운영, 홍보 경험, 보조적 실행 경험 중심, Role 또는 Skill이 부분적
- 1.0~3.6(기초 수준 또는 직무 경험 없음) : 인턴십 기초 역할, 관련 경험 없음, 독립 수행 어려움, KPI 없음

Z축(수행 역량)에 대한 설명이다.

Z축은 '이 사람이 실제로 성과를 냈는가?'를 보는데, 단순히 결과가 있는지를 보는 게 아니다. 성과를 만들어낸 구조가 있는지, 반복할 수 있는지, 확장할 수 있는지를 본다.

Z축 점수 계산 공식
Z = (기여도 × 0.35) + (재현성 × 0.30) + (확장성 × 0.35)
단, 이 공식을 적용하기 전에 Execution Loop → Cap → Gate 순서로 먼저 확인해야 한다.

ACI 기여도 지수 : 이 성과를 낸 것이 본인인가?
RI 재현성 지수 : 같은 성과를 다시 낼 수 있는가?
ISI 확장성 지수 : 이 성과를 다른 곳에도 쓸 수 있는가?

Execution Loop — 실행 반복 구조 '문제를 해결하는 과정을 얼마나 체계적으로 반복했는가'를 보는 개념이다.

Loop 6단계 구조는 아래와 같다.
1단계: 문제 정의  →  '어떤 문제를 해결하려 했는가?'
2단계: 가설 설정  →  '어떤 방법으로 해결할 것인가?'
3단계: 실행       →  '실제로 해봤는가?'
4단계: 측정       →  '결과를 수치로 확인했는가?'
5단계: 개선       →  '결과를 보고 수정·보완했는가?'
6단계: 재적용     →  '개선된 방법을 다시 적용했는가?'

3단계 이하 : 단발성 수행 (한 번 해보고 끝) Z ≤ 3.9점 "해봤습니다" 수준
4단계 : 측정까지 해봄 (1회 개선 구조) Z ≤ 4.1점 "결과를 확인했습니다" 수준
5단계 : 반복 개선 가능 Z ≤ 4.3점 "수정하고 다시 해봤습니다" 수준
6단계 : 자동화/재사용 구조 보유 Z ≥ 4.4점 가능 "다른 곳에도 적용했습니다" 수준

프로젝트를 한 번 진행하고 결과물만 낸 것은 Execution Loop가 아닙니다.
최소 2회 이상 반복하고, 개선한 기록이 있어야 Loop로 인정합니다.

Cap 조건 : 역할에 따른 점수 상한, 지원자가 어떤 역할을 했느냐에 따라 점수 상한이 달라집니다. 아무리 좋은 경험이 많아도, 역할이 보조 수준이면 높은 점수를 줄 수 없습니다.
Support (보조) : 전체 구조 설계 경험 없이 실행을 도왔을 뿐, 4.1점 상한 (데이터 수집, 자료 정리, 보조 실험)
Partial (부분 책임) : 일부 기능이나 모듈은 책임졌지만 전체는 아님, 4.3점 상한 (특정 기능 개발, 부분 실험 설계)
Owner (전체 책임) : 전체 설계·실행·개선을 모두 책임짐, 제한 없음(Gate 충족 필수, 시스템 전체 설계, KPI 책임 경험)

Gate 조건 : Z ≥ 4.5 진입 조건 (3가지 모두 충족해야 함)
① ACI ≥ 4.5  →  본인이 핵심 수행자여야 함 (보조 역할이면 불가)
② RI  ≥ 4.5  →  결과를 재현할 수 있어야 함 ("어떻게 했는지" 설명 가능)
③ ISI ≥ 4.5  →  산업이나 다른 서비스에 적용 가능해야 함
셋 중 하나라도 4.5 미만이면 Z 4.5점 진입은 불가합니다.

Z 축에 대한 점수 산정 기준은 아래와 같다.
5.0(성과를 구조화해서 반복·확장 가능한 최고 수준) : 글로벌 프로젝트 리더, KPI 전후 비교 명확, 실행 Loop 전체 설계 + 반복 개선, ACI/RI/ISI 모두 높음, KPI 명확, Execution Loop 존재, ACI/RI/ISI 모두 충족. 하나라도 없으면 4.9 이하
4.7~4.9(리더로 활약 가능하고 반복 실행이 확인된 수준) : 주요 실무에서 실질 성과, KPI 기반 결과 증명, 재실행 가능한 구조 보유, KPI 존재, 실행 구조 존재, 반복 수행/개선 경험. 확장성 없으면 4.6 이하
4.4~4.6(성과는 있지만 재현성·확장성이 부분적인 수준) : 기업 실무에서 성과 기여, KPI 일부 증명, 실행 및 일부 개선 경험, KPI 일부 존재, 실행 경험 있음. Loop 없으면 4.3 이하
4.1~4.3(성과는 있지만 구조·반복 설명이 약한 수준) : 실무 보조 이상 성과 기여, 실행 경험 있으나 KPI 부분적, 실행 경험 있음, KPI 또는 재현성 설명 부분적
3.7~4.0(기본 수행은 하지만 Loop가 단발성인 수준) : 프로젝트에서 일정 성과, Loop가 단발성, 일정 성과 있음, Loop 구조는 단발성에 가까움
1.0~3.6(보조 역할이거나 경험이 거의 없는 수준) : 보조 역할, 단순 참여, 무경험, Loop/KPI/재현성 모두 약함

0.1점 단위 조정 규칙
점수 구간이 정해진 후에만 0.1점 단위로 세밀하게 조정할 수 있습니다.

0.1점을 더해줄 수 있는 경우
- KPI가 추가로 존재함
- 반복 구조가 명확히 확인됨
- 확장성 설명이 가능함

0.1점을 빼야 하는 경우
- 결과 설명이 모호함
- 구조 설명이 부족함
- 팀 성과를 본인 성과처럼 과장함
- 결과를 재현할 수 없음
